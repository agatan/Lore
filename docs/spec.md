# Koe 要件仕様書

> macOS 専用・完全ローカルの音声入力アプリ。リポジトリ名は `vcin`、プロダクト名は **Koe**（声）。
> 本書は AI エージェントが実装時に参照する正本。人間向けの圧縮版は [docs/overview/index.html](overview/index.html)。
> 設計の詳細は [docs/design.md](design.md)。

- ステータス: Draft v1（2026-08-03 ヒアリング完了）
- オーナー: agatan（唯一のユーザー。自分専用の最強ツールとして開発する）

---

## 1. ビジョンと位置づけ

**「話した内容が、いま作業しているアプリにふさわしい完成文になって挿入される」** を、音声もテキストも一切ネットワークに出さずに実現する。

- 位置づけ: **自分専用の最強ツール**。配布・収益化は非目標。尖った作りで良い。オンボーディングや汎用性より、オーナー自身のワークフロー最適化を優先する。
- 主要利用シーン（すべて対象）:
  1. AI エージェント（AIコーディングツール 等）への長文プロンプト口述
  2. Slack・メール等の日常文章
  3. メモ・思考の書き出し
  4. コーディング中の補助全般（コミットメッセージ、PR 説明、コードコメント）

### 1.1 競合環境と差別化（2026-08 調査）

| 既存アプリ | 弱点 |
|---|---|
| superwhisper | 高価（$249 買切）・設定が複雑・大モデルは遅い |
| Wispr Flow | 完全クラウド。画面スクショのクラウド送信が発覚し炎上。オフライン不可 |
| VoiceInk (OSS) | ローカル + LLM 整形はあるがポリッシュ不足 |
| Handy (OSS) | AI 後処理ゼロ。停止後 2〜5 秒待ち |
| Aqua Voice | 開発者向け精度は最高峰だがクラウド専用 |
| macOS 標準 | 精度低・整形なし・専門用語に弱い |

Koe が突く空白地帯:

1. **完全ローカル × 日本語に強い LLM 整形**（同音異義語、句読点、文体変換）— 全主要アプリが未対応
2. **ローカルで技術用語・日英混在に強い口述** — Aqua Voice はクラウド専用、Whisper 素の技術用語精度は 65% 程度
3. **オンデバイス文脈認識**（アプリ別モード自動切替）— Wispr Flow 炎上でクラウド送信は地雷と証明済み
4. **ローカルで学習する自動辞書提案** — Wispr Flow の自動学習辞書はクラウド前提

## 2. スコープ

### 2.1 v1 スコープ

- グローバルホットキーによる録音（トグル + push-to-talk のハイブリッド）
- 完全ローカル STT（日英自動判定・混在対応）
- ローカル LLM による整形（**最重要機能**）
- アクティブアプリ検出によるモード（整形プロンプト）自動切替
- 整形完了後の一括テキスト挿入（カーソル位置）
- カスタム語彙（手動登録 + **自動提案**）
- 履歴の永続保存・検索・再コピー
- 録音中 HUD（状態表示・逐次文字起こし表示・キャンセル）
- メニューバー常駐 UI・設定画面・モデル管理（ダウンロード/削除）

### 2.2 v1 非スコープ（将来候補）

- 会議録音・音声ファイルの文字起こし（v2 候補。口述入力に集中）
- 生テキスト即挿入 → 整形後置換（挿入先アプリとの相性問題があるため。将来オプション化を検討）

### 2.3 非目標（やらない）

- 音声コマンドによるアプリ操作（アシスタント機能）
- iPhone 連携・macOS 以外への展開
- ~~クラウド STT / クラウド LLM への接続。**BYOK すら提供しない。ローカル専用であること自体が価値**~~
  → **クラウド STT は引き続き非目標**（音声そのものは絶対に外に出さない）。一方、**文章の仕上げに限り BYOK を提供する**（設計 C-62）。オンデバイスモデルの整形品質が実使用に耐えないという実測判断による。既定はオンデバイスのままで、明示的に選んだときだけ文字起こしと指示文が外部 API に送られる。

## 3. 前提・制約

| 項目 | 内容 |
|---|---|
| 対応 OS | **macOS 26 (Tahoe) 以降**。FoundationModels と SpeechAnalyzer を前提とする |
| ハードウェア | Apple Silicon 専用 |
| 実装 | Swift ネイティブ（SwiftUI + AppKit 併用） |
| 権限 | マイク、アクセシビリティ（ホットキー監視・テキスト挿入・前面アプリ検出に必須） |
| ネットワーク | **モデルのダウンロード時のみ使用**。音声・文字起こし・整形テキスト・語彙・履歴は一切送信しない |
| 配布 | 自分ビルド。公証・App Store 対応は不要 |

## 4. 機能要件

### FR-1 録音の起動・停止

- FR-1.1 グローバルホットキー 1 つで制御する。デフォルトキーは設定可能（Fn、右 Option、F13 等）。
- FR-1.2 **短押し（閾値未満で離す）= トグル開始**。再度短押しで停止。
- FR-1.3 **長押し（閾値以上保持）= push-to-talk**。離した瞬間に停止して処理開始。閾値はデフォルト 300ms、設定可能。
- FR-1.4 録音中の Esc キー（または HUD のキャンセル操作）で**破棄キャンセル**。挿入は行わないが、確定済みの文字起こしは履歴に `cancelled` として残す（FR-7）。
- FR-1.5 録音開始・停止・キャンセル・完了で効果音（設定でオフ可）。
- FR-1.6 他アプリが前面でも、どのアプリにフォーカスがあっても動作する。

### FR-2 音声認識（STT）

- FR-2.1 完全オンデバイスで動作する。
- FR-2.2 エンジンは差し替え可能な抽象の下に 2 系統を実装する:
  - **SpeechAnalyzer**（macOS 26 標準）: デフォルト。低レイテンシ・ストリーミング。
  - **WhisperKit**（CoreML）: 高精度系。whisper-large-v3-turbo、日本語特化の kotoba-whisper 等をモデル選択可能。
- FR-2.3 **日英自動判定**: 発話言語を自動判定して認識する。文中の日英混在（カタカナ技術用語・英単語まじり日本語）を実用レベルで扱う。
- FR-2.4 録音中にストリーミングで暫定結果を生成し、HUD に逐次表示する（FR-8）。録音停止時点で残る未確定部分のみを確定処理し、停止後レイテンシを最小化する。
- FR-2.5 カスタム語彙（FR-6）を STT 段階でも可能な範囲でバイアスに利用する（Whisper の initial prompt 等）。

### FR-3 LLM 整形 — 最重要機能

- FR-3.1 生の文字起こしをローカル LLM で整形してから挿入する。整形の内容は現在のモード（FR-4）のプロンプトで決まる。
- FR-3.2 基本整形（全モード共通の責務）:
  - フィラー除去（「えーと」「あのー」「um」等）
  - 句読点・改行の自然な挿入
  - 言い直し・繰り返しの整理（後に言った方を採用）
  - 同音異義語の文脈に基づく選択
  - カスタム語彙による固有名詞・技術用語の表記矯正
- FR-3.3 モード別整形: 文体変換（です・ます／だ・である／カジュアル）、英訳（AI エージェント向け等、モード設定次第）、マークダウン整形など、モードのプロンプトで自由に指定できる。
- FR-3.4 LLM エンジンは差し替え可能な抽象の下に 2 系統を実装する:
  - **アプリ内蔵（MLX）**: デフォルト。アプリがモデル（例: Qwen3-4B 系 4bit）をダウンロード・管理する。
  - **Apple Foundation Models**: macOS 標準のオンデバイスモデル。セットアップ不要のフォールバック／軽量選択肢。
- FR-3.5 整形は「変換」であり「応答」ではない。入力が質問文でも LLM は答えず、整形のみ行うようプロンプトを設計する。
- FR-3.6 整形失敗（タイムアウト・モデル未ロード・出力異常）時は**生の文字起こしをそのまま挿入**にフォールバックし、HUD で整形スキップを通知する。発話内容を失うことは許されない（NFR-3）。
- FR-3.7 整形出力の検証: 出力が空、入力比で極端に短い/長い場合は異常とみなし FR-3.6 のフォールバックに入る。

### FR-4 モードとアプリ別自動切替

- FR-4.1 モード = 名前 + マッチャー（アプリの bundle ID のリスト）+ 整形プロンプト + 任意の LLM モデル指定、からなる設定単位。
- FR-4.2 録音開始時点の前面アプリからモードを自動選択する。マッチしなければデフォルトモード。
- FR-4.3 ビルトインモード（初期設定として同梱、編集・削除可能）:
  | モード | 対象アプリ例 | 整形方針 |
  |---|---|---|
  | Default | （フォールバック） | 基本整形のみ |
  | AI Agent | ターミナル各種, IDE | 基本整形 + 指示文として明瞭に。技術用語を正確に |
  | Chat | Slack, Discord | カジュアル・短文・改行少なめ |
  | Mail / Docs | メーラー, ブラウザ | です・ます調、段落整形 |
  | Memo | メモ系アプリ | 話し言葉を残しつつ箇条書き整理 |
- FR-4.4 モードは設定画面で作成・編集・複製・削除できる。プロンプトは自由記述。
- FR-4.5 手動オーバーライド: メニューバー／HUD から次回のモードを一時的に固定できる。
- FR-4.6 適用されたモードとプロンプトの内容は履歴にスナップショットとして記録する（NFR-4 再現性）。

### FR-5 テキスト挿入

- FR-5.1 整形完了後、録音開始時にフォーカスがあったアプリのカーソル位置へ**一括挿入**する。
- FR-5.2 挿入方式はペーストボード経由（クリップボード退避 → 挿入 → 復元）を基本とし、確実性を優先する。
- FR-5.3 挿入に失敗した場合（フォーカス喪失、セキュア入力フィールド等）、テキストをクリップボードに残して通知する。**結果が消えることはない**。
- FR-5.4 挿入直後、最後の結果をメニューバーから再コピーできる。

### FR-6 カスタム語彙

- FR-6.1 語彙エントリ = 正しい表記（surface）+ 読み（任意）+ よくある誤認識パターン（任意・複数）+ メモ。
- FR-6.2 語彙は LLM 整形プロンプトに注入し、誤認識の矯正・表記統一に用いる。対応エンジンでは STT バイアス（FR-2.5）にも用いる。
- FR-6.3 設定画面で追加・編集・無効化・削除できる。
- FR-6.4 **自動提案**: 履歴をローカル LLM が定期分析し、辞書候補を提案する。
  - 検出対象: (a) 頻出する固有名詞・技術用語で未登録のもの、(b) 生文字起こしと整形結果の差分に繰り返し現れる矯正パターン、(c) 表記ゆれ（同一語の複数表記）。
  - 候補は根拠（出現回数・出現例）付きで提示し、**ユーザーが承認して初めて辞書に登録される**。却下した候補は再提案しない。
  - 分析は完全ローカルで、アイドル時にバックグラウンド実行する。

### FR-7 履歴

- FR-7.1 全セッションをローカル DB に永続保存する。保存項目: 日時、挿入先アプリ、適用モード（プロンプトのスナップショット含む）、使用エンジン・モデル、判定言語、**生の文字起こし**、**整形後テキスト**、ステータス（completed / cancelled / failed / fallback）、各段レイテンシ。
- FR-7.2 履歴ウィンドウで一覧・全文検索・再コピー（生／整形後どちらも）ができる。
- FR-7.3 保持期間は設定可能（デフォルト無期限）。個別削除・全削除ができる。
- FR-7.4 音声データそのものは保存しない（デバッグ用に直近 1 件のみ保持するオプションは可）。

### FR-8 HUD・メニューバー UI

- FR-8.1 メニューバー常駐アプリ（Dock アイコンなし）。メニューから: 録音開始、モード一時固定、最後の結果を再コピー、履歴、設定、終了。
- FR-8.2 録音中は小型のフローティング HUD を表示（フォーカスを奪わない）。表示内容: 録音状態・入力レベル（波形またはレベルメーター）・現在モード名・**逐次文字起こしの暫定表示**。
- FR-8.3 停止後は HUD が「認識中 → 整形中 → 挿入完了」と状態遷移を表示し、完了後に自動で消える。
- FR-8.4 HUD から Esc でキャンセルできる（FR-1.4）。

### FR-9 モデル管理

- FR-9.1 設定画面から STT / LLM 各モデルの一覧・ダウンロード・削除・使用モデル切替ができる。
- FR-9.2 モデルダウンロードが唯一のネットワーク通信であることを UI 上に明記する。
- FR-9.3 初回起動時、モデル未取得でも SpeechAnalyzer + Foundation Models の組で即使い始められる（追加ダウンロード不要の構成をデフォルトにする）。

### FR-10 設定

- FR-10.1 ホットキー・長押し閾値、効果音、HUD 表示、履歴保持期間、モデル選択、モード編集、語彙管理、ログイン時起動。
- FR-10.2 設定はローカルファイル（plist / DB）に保存する。エクスポート・インポートは v1 非スコープ。

## 5. 非機能要件

### NFR-1 レイテンシ

録音停止 → テキスト挿入完了までの体感が製品価値を決める。

| 指標 | 目標 |
|---|---|
| 停止 → 挿入完了（発話 30 秒以内、デフォルト構成） | p50 ≤ 1.5 秒 / p95 ≤ 3 秒 |
| 録音開始ホットキー → 録音開始 | ≤ 100ms |
| ストリーミング STT | 録音中に処理を進め、停止時の残処理を最小化する（FR-2.4） |

各セッションのステージ別レイテンシを履歴に記録し、劣化を観測可能にする（NFR-4）。

### NFR-2 プライバシー

- 音声・文字起こし・整形テキスト・語彙・履歴・画面情報を**一切ネットワークに送信しない**。
- ネットワークアクセスはモデルダウンロード処理のみに隔離し、コードレビューで検証可能な構造にする。
- 前面アプリの検出は bundle ID の取得のみ。画面内容・ウィンドウ内テキストは v1 では読まない。

### NFR-3 信頼性 — 「発話を失わない」

最重要の不変条件: **ユーザーが話した内容は、いかなる失敗経路でも復元可能でなければならない**。

- STT 確定結果は整形開始前に永続化する。
- 整形失敗 → 生テキスト挿入にフォールバック（FR-3.6）。
- 挿入失敗 → クリップボードに保持 + 通知（FR-5.3）。
- クラッシュ後も、確定済み文字起こしは履歴から回収できる。

### NFR-4 可観測性・再現性

- 各セッションについて「どの入力に、どのモード・プロンプト・モデルが適用され、何が出力されたか」を後から完全に説明できる（履歴のスナップショット記録）。
- プロンプトやモデルを変更しても、過去の履歴は当時の適用内容を保持する。

### NFR-5 常駐アプリとしての行儀

- アイドル時 CPU 使用率 ~0%、メモリはモデル非ロード時 200MB 以下を目安とする。
- LLM / STT モデルのロード・アンロード戦略を持つ（アイドル一定時間でアンロード、など。体感レイテンシとのトレードオフは設定可能に）。
- ログイン項目への登録はユーザーの明示操作のみ。

## 6. 受け入れシナリオ（抜粋）

1. **AI エージェント指示**: ターミナルで AIコーディングツール を開き、ホットキー長押しで「えーとこの関数をリファクタして、あーやっぱりテストも一緒に書いて」と話して離す → 3 秒以内に「この関数をリファクタリングして、テストも一緒に書いてください。」がカーソル位置に挿入される。
2. **Slack カジュアル**: Slack で短押しトグル録音 →「明日の 1on1 なんですけど 30 分後ろにずらしてもらえると助かります」→ カジュアル文体に整形されて挿入。
3. **語彙矯正**: 「ヘンリー」が「変理」と誤認識されても、語彙登録済みなら整形後は「ヘンリー」になる。
4. **語彙自動提案**: 数日使用後、設定画面に「『レセコン』を辞書に追加しますか？（12 回出現）」等の提案が根拠付きで並び、承認すると以後の整形に反映される。
5. **整形失敗フォールバック**: LLM がタイムアウトしても、生の文字起こしが挿入され、HUD に「整形をスキップしました」と表示される。
6. **キャンセル**: 録音中に Esc → 何も挿入されず、履歴に cancelled として文字起こしが残る。

## 8. スパイク結果（2026-08-03 実測）

### S-2 Foundation Models の日本語整形品質

macOS 26.5 / Apple Intelligence 有効の環境で、実装した整形プロンプトを通して実測した。

| 観点 | 結果 |
|---|---|
| レイテンシ | 0.7〜1.4 秒（発話 30 秒相当まで）。NFR-1 の p50 ≤1.5 秒は LLM 単体では達成 |
| 基本整形 | 実用。フィラー除去・句読点・言い直しの整理は問題なし。「一on一」→「1on1」「三十分」→「30 分」も正しい |
| 質問文 | 答えずに質問文のまま整形できた |
| ガードレール | 医療的な内容（体温・当直医への連絡）でも拒否されなかった（`permissiveContentTransformations` 使用） |
| **語彙表への追従** | **不可**。「最優先」と書いても登録済みの誤認識をそのまま出す → 誤認識置換はコード側で決定的に行う設計に変更（design C-9） |
| **数値** | 当初「三十八度五分」→「38.08 度」と壊した。few-shot と明示ルールの追加で解消 |
| **長文** | 当初、工程を勝手に分解しコードブロックで手順書を出力した（＝応答してしまった）。命令を入力の後ろに置き直して解消（design C-10） |
