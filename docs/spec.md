# Koe 要件仕様書

Koe は macOS 専用の音声入力アプリです。話した内容を文字にし、利用中のアプリに合う文章へ整えてカーソル位置へ挿入します。

本書は現在の機能要件を示します。データの取り扱いは [PRIVACY.md](../PRIVACY.md)、実装構造は [design.md](design.md) を正本とします。

## 1. 目的

口述から文章挿入までを一つの追跡可能なセッションとして扱い、次を実現します。

- ホットキーからすぐ録音を開始できる。
- 認識結果を用途に合う文章へ整える。
- 整形や挿入が失敗しても発話内容を回収できる。
- どのルールとモデルで結果が作られたかを後から説明できる。

## 2. スコープ

### 2.1 対象

- グローバルホットキーによるトグル録音と push-to-talk
- Apple SpeechAnalyzer によるオンデバイス音声認識
- Apple Foundation Models または Groq API による文章整形
- 前面アプリに応じたモード選択
- 共通ルールとカスタム語彙
- 整形後テキストのカーソル位置への挿入
- 履歴の保存、検索、再コピー、削除
- 履歴からの語彙候補のオンデバイス分析
- メニューバー、HUD、設定画面

### 2.2 非目標

- クラウド音声認識
- 口述セッションの録音音声の保存（ライフログの明示的な継続保存は対象）
- 会議録音や音声ファイルの文字起こし
- 音声コマンドによるアプリ操作
- macOS 以外への対応

## 3. 前提と境界

| 項目 | 内容 |
|---|---|
| OS | macOS 26 以降 |
| ハードウェア | Apple Silicon |
| 権限 | マイク、アクセシビリティ |
| 音声認識 | Apple SpeechAnalyzer。口述音声は保存しない。ライフログ音声は有効時だけローカル保存し、送信しない |
| 既定の整形 | Apple Foundation Models。外部送信しない |
| 任意の整形 | Groq。利用者が選んだ場合だけ文字起こしと指示文を送信する |
| 保存 | SQLite。履歴の既定保持期間は無期限 |

外部送信の有無は `FormattingBackend` で表現します。組織や用途による文章の差はモードと共通ルールで表現し、音声入力パイプラインへ個別条件を散らしません。

## 4. 機能要件

### FR-1 録音操作

- 短押しは録音開始・停止のトグルとして扱う。
- 長押しは push-to-talk として扱い、離した時点で停止する。
- 既定ホットキーは右 Option、既定の長押し閾値は 500 ms とする。
- 録音中の Esc は挿入を取り消す。認識済みの文字があれば `cancelled` の履歴として残す。
- 同時に進行できる口述セッションは一つだけとする。

### FR-2 音声認識

- SpeechAnalyzer でストリーミング認識し、暫定テキストを HUD に表示する。
- 音声認識はオンデバイスで実行する。
- macOS が必要な音声アセットを管理する。未取得の場合は、利用者の操作で取得を開始する。
- モードの言語設定と語彙を認識ヒントとして利用する。
- 口述で録音した音声は永続化しない。ライフログのcapture pipelineとは共有しない。

### FR-3 文章整形

- 既定では Apple Foundation Models を使用する。
- 利用者は Groq API を明示的に選択できる。
- Groq 利用時に送信するのは、今回の文字起こし、共通ルール、モード指示、語彙に限る。
- 質問への回答ではなく、入力された文章の変換だけを行う。
- 空出力、極端な長さ、プロンプト漏洩などを検出したら異常とする。
- タイムアウト、利用不可、異常出力の場合は、生の文字起こしをそのまま挿入する。
- 利用したエンジンとモデルを履歴へ記録する。

### FR-4 モードと共通ルール

- モードは名前、bundle ID のパターン、整形指示、言語設定、任意のモデル指定を持つ。
- 録音開始時の前面アプリからモードを一度だけ解決し、そのセッション中は変更しない。
- 手動固定はアプリによる自動選択より優先する。
- モードは作成、編集、削除、並べ替えできる。
- 全モードに適用する共通ルールを別に管理する。
- 実際に使ったモードと最終プロンプトを履歴へスナップショットとして保存する。

### FR-5 テキスト挿入

- 整形完了後、録音開始時に対象だったアプリへ一括挿入する。
- クリップボードを退避し、結果を設定してペーストし、成功後に元の内容を復元する。
- 挿入できなかった場合は結果をクリップボードに残し、利用者へ通知する。

### FR-6 語彙

- 語彙は表記、読み、誤認識パターン、メモを持つ。
- 有効な語彙を音声認識のヒントと整形プロンプトへ渡す。
- 履歴から語彙候補を分析し、出現回数と抜粋を根拠として提示する。
- 語彙候補の分析は、Groq が整形に選ばれていても必ずオンデバイスで実行する。
- 候補は利用者が承認したときだけ語彙へ登録する。

### FR-7 履歴

- STT 確定後、整形を始める前に履歴を永続化する。
- 履歴には日時、対象アプリ、モードとプロンプト、エンジンとモデル、生の文字起こし、整形結果、状態、エラー、処理時間を保存する。
- 状態は `interrupted`、`completed`、`cancelled`、`failed`、`fallback`、`clipboard_only` を区別する。
- 履歴は全文検索、再コピー、個別削除、一括削除ができる。
- 保持期間は設定でき、`0` は無期限を表す。
- 語彙候補の根拠抜粋は履歴と別に保存する。履歴削除後も残ることを削除確認画面で明示する。

### FR-8 UI

- Dock に常駐せず、メニューバーから主要操作へアクセスできる。
- HUD は録音、認識、整形、挿入、終了の状態を表示する。
- 設定画面は、現在選択している整形方式に応じて外部送信の有無と対象を表示する。
- 履歴画面は、結果とその生成根拠を確認できるようにする。

### FR-9 設定と秘密情報

- ホットキー、長押し閾値、効果音、HUD、保持期間、整形方式、Groq モデルを設定できる。
- Groq API キーは macOS Keychain に保存する。
- API キーを設定 JSON、履歴 DB、ログへ保存しない。
- 未知の設定値があっても、関係のない設定を失わず、該当項目だけ既定値へ戻す。

## 5. 非機能要件

### NFR-1 ドメイン整合性

中心となるビジネス概念は「口述セッション」です。録音開始時の対象アプリ、モード、指示、エンジンを一つのコンテキストとして確定し、途中変更で結果の意味が変わらないようにします。

### NFR-2 プライバシー

- 口述音声は保存・送信しない。ライフログ音声は利用者が有効化した場合だけMac内へ保存し、外部送信しない。

## 7. ライフログ

- KoeのメインWindow上部でライフログと音声入力をtab切り替えし、既定はライフログとする。ライフログでは月間の予定・発話密度をdotで示すCalendar、summary、timestamp付き全発話、global TODO、その日のリズムを扱う。
- 設定は別Windowで開き、共通・音声入力・ライフログの階層に分ける。
- CalendarのRSVPは読み取り専用で扱い、アプリ内に返答やCalendarへの遷移動線を設けない。既定では参加済みとRSVPのない予定だけを表示・派生処理へ含める。
- 予定時刻は発話の参考情報とし、予定の切り替わりだけでconversationを分割しない。関連付けは前後2分のずれを許容する。
- Continuous Captureは口述と独立した状態を持ち、完成音声チャンクをローカル確定してからSTTへ渡す。未処理chunkは起動後に再実行する。
- source of truthは `local raw audio → timestamped transcript → conversation → TODO/summary` の順とする。
- EventKitの予定は最小snapshotとして保存し、発話との関連はoptionalとする。
- Conversationは予定の境界では切らず、90秒以上の無発話で決定論的に区切る。
- SummaryとTODO案は通常の成形と同じ設定済みLLM（Foundation ModelsまたはGroq）で、ライフログ記録がONの間、設定間隔ごとに生成する。前回以降の発話・メモがない定期実行ではLLMを呼ばない。更新時は当日の全データを使い、入力枠を超える場合だけ分割と統合で複数回呼び出す。停止時は差分の有無にかかわらず、発話またはメモのある対象日を全データから再要約する。TODO案は編集して確定するか棄却でき、未確定案だけを次回生成時に置き換える。
- 時刻や集中モードなどを条件にした自動開始・終了は、macOSショートカットのオートメーションからKoeのApp Intentを実行する。
- 録音開始から停止までSpeechAnalyzerの入力ストリームを維持する。30秒ごとのローカル音声保存は復旧境界であり、認識セッションの境界にはしない。音声入力が中断した場合は保存済み音声を残し、記録が有効な間だけ自動再接続する。
- ライフログと短い音声入力は、それぞれ専用のSpeechAnalyzer/Transcriberセッションとして同時に利用できる。スリープ前には実行中の音声ストリームを閉じ、ライフログの記録意図だけを保持して復帰後に新しいセッションへ自動再接続する。
- ミニウィンドウからチャット形式でテキストメモを追加できる。メモは発話と異なる型・印で保存・表示し、Summary・TODO案とエクスポートで出典を区別する。
- 明確な無音chunkは入力レベルを根拠に再起動時の再文字起こしと後続派生処理を省略する。判定不能な旧データと静かな発話は処理する。
- 連続記録が日付をまたいでも認識セッションは維持し、発話・メモ・会話・Summaryを実時刻の各日へ分ける。日付変更時は前日Summaryを確定し、追従表示を新しい日に切り替える。
- Summaryは設定した30分・1時間・2時間の間隔を満たし、前回更新後に発話またはメモが増えた時だけ更新する。更新時は以前のsummaryではなく、その日の全発話・メモ・予定を時系列で渡す。1回の入力枠に収まらない場合は全データを分割要約して統合する。音声保存chunkごとにはLLMを呼ばない。
- ライフログのSummary・TODO promptとTODO抽出ruleは設定画面から編集できる。
- 記録の開始・停止とミニウィンドウの表示切り替えは、音声入力とは別のglobal hotkeyを設定できる。
- 「ライフログを開始」「ライフログを終了」をmacOSのショートカットAppで利用できるアクションとして公開し、UIを開かず冪等に実行できる。
- 「ライフログを終了」は最終文字起こしと停止時の再要約が完了してから成功を返す。日別ファイル書き出しは日付省略時に実行日の今日を使い、任意の出力先フォルダと `{{date}}`（yyyyMMdd）を含むファイル名を指定できる。同名ファイルへの再実行は最新内容で置き換える。
- STTは既存VocabularyStoreを共有する。
- 既定構成では文字起こしと指示文を外部送信しない。
- Groq を選んだ場合だけ、画面で明示したデータを文章整形のために送信する。
- Groqでライフログを派生処理する場合、対象日の全発話とテキストメモ、予定の時刻と件名、ライフログpromptと抽出ruleを送信する。録音音声、通常の口述履歴、前面アプリ情報は送信しない。
- 語彙分析は常にオンデバイスで行う。
- 画面やウィンドウ内の内容を読み取らない。

### NFR-3 信頼性

- STT 確定後の文字起こしを、整形開始前に保存する。
- 整形失敗時は生テキストを使用する。
- 挿入失敗時はクリップボードへ結果を残す。
- 進行中の記録は `interrupted` として識別できる。

### NFR-4 説明可能性

- 入力、適用ルール、エンジン、モデル、結果、状態遷移を後から確認できる。
- 設定変更後も、過去の履歴は当時のスナップショットを保持する。
- 重要な失敗はログまたは履歴に理由を残す。発話内容や秘密情報はログへ出さない。

### NFR-5 性能と常駐動作

- 録音開始はホットキー操作から 100 ms 以内を目標とする。
- 30秒以内の発話について、停止から挿入まで p50 1.5秒、p95 3秒を目標とする。
- エンジンとモデルごとの処理時間を履歴から集計する。
- ログイン項目への登録は利用者の明示操作で行う。

## 6. 受け入れ条件

1. オンデバイス整形では、文字起こしが外部APIへ送られない。
2. Groq 整形では、送信前に設定画面で対象データを確認できる。
3. Groq 選択中でも、語彙分析はオンデバイスエンジンを使用する。
4. 整形が失敗しても、生の文字起こしを挿入または履歴から回収できる。
5. 挿入が失敗しても、結果がクリップボードに残る。
6. 履歴から、結果を作ったモード、指示、エンジン、モデルを確認できる。
