Koe 外部仕様

利用者、macOS Shortcuts、CLI、MCP clientから観測できる現在の製品契約です。画面、設定、保存、障害時挙動、automation interfaceを一つにまとめています。

1. 動作環境と製品境界

項目 仕様
OS / CPU macOS 26以降 / Apple Silicon
形態 Menu bar常駐app。Dockには常駐しない
必須権限 録音にmicrophone、cursor位置への挿入にaccessibility
任意権限 Life logへ予定を表示するcalendar
STT Apple SpeechAnalyzerによるオンデバイス認識。Cloud STTなし
既定LLM Apple Foundation Models。Mac外へ送信しない

対象外はmacOS以外、音声fileの一括文字起こし、音声commandによるapp操作、通常の音声入力audioの保存、cloud STTです。

2. 初回起動と権限

  • Onboardingでmicrophone、入力操作、任意のcalendar権限と保存範囲を説明します。
  • 通常起動ではmenu bar常駐に加えてmain windowを開き、life logを選択した状態で表示します。
  • Microphone権限がなければ録音できず、accessibility権限がなければ対象appへ挿入できません。Calendar権限は音声入力には不要です。
  • Life logの初回開始前に30秒単位の復旧用audioをMac内へ保存する明示同意が必要です。同意前のShortcuts開始はKoeを開くようerrorを返します。

3. 音声入力

操作と認識

Hotkey

既定は右Option。短押しはtoggle、500ms以上の長押しはpush-to-talk。Escでcancelします。

状態表示

録音、認識、整形、挿入、完了/失敗をHUDとmenu barへ表示。効果音、HUD、level表示は設定できます。

Audio

SpeechAnalyzerへstreamします。通常の音声入力audioはfileやDBへ保存せず、外部へ送りません。

Mode、rule、語彙

  • 録音開始時の前面appからmodeを決め、session中は固定します。手動固定を優先します。
  • Modeは名前、bundle ID pattern、指示、言語、任意modelを持ち、CRUDと並べ替えができます。
  • 共通ruleは全modeへ適用します。
  • 語彙は表記、任意の読み、誤認識pattern、有効/無効を持ち、STT hintと文章処理へ反映します。
  • 履歴由来の語彙候補はオンデバイスで分析し、利用者の承認後だけ登録します。

文章処理先

Backend 送信
Apple Foundation Models Mac内
Ollama localhost:11434
LM Studio localhost:1234
OpenAI / Anthropic / Gemini / Groq 明示選択時だけproviderへ文字dataを送信

Cloudへ送るのは今回の文字起こし、共通rule、mode指示、有効な語彙です。録音audio、過去履歴、前面app情報、API keyはprompt dataに含めません。

ボイスメモ

  • 専用global hotkey、main windowとmini windowのmemo入力欄にある音声ボタンは、いずれも押すたびに録音開始・停止を切り替え、認識した生textを今日のlife-log memoとして保存します。文章整形、前面appへの挿入、通常の音声入力履歴への保存は行いません。
  • Memo入力欄の音声ボタンは、開始準備中をprogress表示、録音中を録音色とpulse animationで示し、通常の音声入力など別の音声処理中は新規開始できません。
  • Life log記録中は現在の復旧用audio chunkを確定してcaptureを一時停止し、ボイスメモの完了、cancel、失敗後に記録開始意図が残っている場合だけ自動再開します。
  • 一回のボイスメモはmemo一件だけを作り、通常の音声入力履歴やlife-log utteranceへ同じ内容を追加しません。

4. Life log

継続記録

  • 通常の音声入力と独立し、同時利用できます。Menu bar、main window、専用hotkey、Shortcutsから開始・停止します。
  • Life logが実際に録音している間は、menu barにKoeのapp iconを主表示し、その右下へ録音色の小さなbadgeを重ねます。停止中と再接続待ちでは通常のmonochrome表示へ戻し、再接続待ちを録音中とは表示しません。
  • 音声入力との同時利用中も、復旧可能なlife-log audioの記録は中断しません。音声入力が成功した区間はそのraw transcriptを正本とし、同じ録音時間帯にlife log側で認識した発話はtimeline、検索、書き出し、summary/TODO生成へ重複して出しません。音声入力がcancelまたは失敗した場合は、life log側の発話を残します。
  • 選択したinput deviceから記録し、30秒ごとに復旧用.m4aをMac内へ確定します。Audioをcloud STTへ送ることはありません。
  • 保存済みaudioは文字起こしと派生処理が両方成功するまで必ず保持します。既定の「処理後削除」では成功直後にaudioだけを削除し、保存済みの発話、conversation、summary、TODOは残します。設定は「処理後削除」「7日」「30日」から選べます。
  • 7日または30日を選んだ場合も、未処理・失敗chunkは期間を超えて保持し、次回起動後の再処理に使います。保持期間を短く変更したときは、新しい条件を満たす処理済みaudioを削除します。
  • 一時中断と既定マイクの切替・接続解除などの音声構成変更では、現在のchunkを確定して自動再接続します。Sleep前にも閉じ、記録意図が残ればwake後に再開します。マイク権限拒否だけは自動再試行しません。

日別表示とCalendar

Month

予定と発話activityを日単位で表示します。

Timeline

時刻付き発話、text memo、calendar予定を区別します。今日のtimeline最下部とmini windowには同じchat形式の入力欄があり、送信したmemoを今日のtimelineへ即時追加します。ボイスメモも手入力と同じmemoとして追加します。過去日の履歴へ現在のmemoを混入させないため、main windowの入力欄は今日を選択中だけ表示します。

Conversation

90秒以上の無発話で分割。予定との関連は前後2分を許容します。

Calendar

選択calendarの最小snapshotを読取専用で保存。既定は参加済み/RSVPなしだけを対象にします。Calendar設定の「予定を再取得」は現在timelineで選択中の日を読み直し、timelineと月間activityを更新します。

SummaryとTODO

  • 30分、1時間、2時間の設定間隔でsummaryとdraft TODOを同時更新します。
  • 差分がある時だけ、その日の全発話、memo、対象予定から作り直します。入力上限超過時は時系列に分割して統合します。
  • 当日のlive summaryには生成時刻を基準時点として渡し、予定を「終了済み」「進行中」「これから」に区別します。開始前の予定を実施済みの事実として書かず、「このあと予定されている」内容として明示します。
  • 日付が変わった後のfinal summaryは、発話やmemoの追加がなくても対象日の全予定を含めて作り直し、isFinalとして保存します。
  • 停止時に対象日を最終更新し、audio chunkごとにはLLMを呼びません。
  • Draft TODOは編集して確定または棄却できます。再生成で置換するのはdraftだけです。
  • TODO状態はdraft、open、completed。UI、CLI、MCPから操作できます。
  • Cloud派生処理は対象日の発話、memo、予定の時刻/件名、指示文を送ります。Audio、通常の音声入力履歴、前面app情報は送りません。
  • Groqでは選択modelにかかわらず、summaryとTODO案を温度0、modelが対応する最小の推論量、共通のJSON出力contractで生成します。APIが対応する最も強いschema制約を使い、最終的にKoeが同じ型として検証します。推論本文は応答dataへ含めません。

検索と書き出し

発話、memo、TODO、summaryを横断検索します。日別exportではcalendar、発話、memo、summary、その日に作成/完了したTODOを選択でき、open TODO全体も別にexportできます。

6. 保存、backup、削除

Data 保存先 既定保持
履歴、mode、語彙、life log、TODO、利用量 Application Support/Koe/koe.sqlite 履歴は無期限
Life-log audio Application Support配下 文字起こし・派生処理の成功後に削除。7日または30日へ変更可能
設定 UserDefaults app data削除まで
API key macOS Keychain 個別削除まで
DB backup Application Support/Koe/Backups/ 最新7file
  • 未適用migration直前と、同日重複なしの1日1回にDB backupを作ります。失敗時はmigrationしません。
  • 「全dataを削除」はDB内利用者data、保存audio、DB backupを削除します。設定とKeychainは画面に示す個別範囲に従います。
  • 語彙候補に複製済みの根拠は、履歴だけの削除では残る場合があります。

8. CLI

Build productはkoe-cli、配布/link後はkoeです。失敗はstderrとexit status 1で返します。

koe export day [--date YYYY-MM-DD] [--include calendar,speech,memos,summary,todos] [--clipboard|--output PATH]
koe export todos [--clipboard|--output PATH]
koe todo list [--status open|draft|completed|all]
koe todo add "タイトル" | complete ID | reopen ID | delete ID
koe prompt get summary|todo
koe prompt set summary|todo "プロンプト"   # - で標準入力
koe search "検索語" [--limit N]

--clipboardと--outputは同時指定できません。--output .は既定filenameを現在directoryへ書きます。

9. MCP

koe-mcpは1行1JSONのstdio JSON-RPC serverです。Protocol 2025-03-26、server 1.0.0。Tool errorはresponseのisError: trueとtextで返します。

Tool Arguments
life_log_export date?, include?
todo_export_open なし
life_log_search query, limit?
todo_list status?: open|draft|completed|all。省略時open
todo_add title
todo_update id, title?, status?
todo_delete id
prompt_get kind: summary|todo
prompt_set kind, value

life_log_export.includeはcalendar、speech、memos、summary、todosです。

10. 障害時の外部挙動

STT

確定不能はfailed。Process再起動が必要なら利用者へ案内します。

LLM / Insert

整形失敗はrawへfallback。挿入失敗はclipboardへ結果を残します。

DB

初期化、保存、検索、backup失敗を成功扱いせず、画面/CLI/MCP/logへ理由を出します。

Life log

記録中断は有効中だけ再接続。停止timeoutでも保存済みaudioは次回再処理します。

11. 受け入れ条件

  1. オンデバイス構成では文字起こしと指示文がMac外へ送られない。
  2. Cloud構成は明示選択後だけ使われ、送信範囲を設定画面で確認できる。
  3. 通常の音声入力audioは保存されず、life-log audioは同意後だけ保存される。
  4. 整形失敗後もraw transcript、挿入失敗後もclipboardから内容を回収できる。
  5. 履歴から当時のmode、指示、provider、model、結果、状態を確認できる。
  6. 保留life-log chunkは再起動後に再処理される。
  7. Migration前backupと日次backupが作られ、合計7file以内に保たれる。
  8. CLI、MCP、Shortcutsの公開interfaceが本書と一致する。
  9. Life logの実録音中だけmenu barにKoeのapp iconと右下の録音色badgeが表示され、停止または再接続待ちでは通常表示へ戻る。
  10. Life log記録中に成功した音声入力は一件だけ表示・検索・書き出し・派生処理へ現れ、cancelまたは失敗した音声入力の時間帯はlife-log発話が失われない。
  11. 当日のlive summaryは未来の予定を実施済みとして書かず、日付変更後のfinal summaryはその日の全予定を含む。
  12. Calendar設定から予定を再取得すると、現在選択日のsnapshot、timeline、月間activityが更新される。
  13. マイク切替などの音声構成変更後も、記録開始意図が残る限りlife-log captureが自動再開する。
  14. ボイスメモ一回につきmemoだけが一件作られ、通常の音声入力履歴とlife-log utteranceには同じ内容が追加されない。
  15. 通常起動時にmain windowのlife-log画面が開き、memo入力欄の音声ボタンは専用hotkeyと同じボイスメモを開始・停止する。
  16. 「処理後削除」でも未処理・失敗chunkは残り、文字起こしと派生処理が成功したaudioだけが削除される。
細かなparameterと受け入れ条件は Markdown版、実装の配置は 内部設計 を参照してください。
