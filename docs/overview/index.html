Koe — 完全ローカルの macOS 音声入力

話した内容が、いま作業しているアプリにふさわしい完成文になって挿入される。
音声もテキストも一切ネットワークに出さない。

自分専用の最強ツール macOS 26+ / Apple Silicon Swift ネイティブ 日英自動判定・混在OK LLM 整形が最重要機能

なぜ作る — 空白地帯を突く

既存プレイヤーは多いが、「完全ローカル × 賢い LLM 整形 × 日本語」を満たすものが存在しない。

既存アプリ致命的な穴
superwhisper$249 買切・設定が複雑・大モデルは遅い
Wispr Flow完全クラウド。画面スクショ送信が発覚し炎上
Aqua Voice開発者向け精度は最高峰だがクラウド専用
VoiceInk / Handy (OSS)整形が弱い or ゼロ。ポリッシュ不足
macOS 標準精度低・整形なし・専門用語に弱い
Koe の賭け所: ① ローカル LLM による日本語整形（フィラー・同音異義語・文体変換）② 技術用語・日英混在に強い口述 ③ オンデバイス文脈認識（アプリ別モード）④ ローカルで学習する辞書自動提案

整形失敗 → 生テキストを挿入。挿入失敗 → クリップボードに保持して通知。どの失敗経路でも発話内容は復元可能（最重要の不変条件）。停止→挿入の目標: p50 ≤ 1.5 秒。

主要機能

アプリ別モード自動切替

前面アプリの bundle ID でモードを自動選択。ターミナル→AI 指示文、Slack→カジュアル、メール→です・ます。プロンプトは自由編集、手動固定も可。

LLM 整形

フィラー除去・句読点・言い直し整理・同音異義語の文脈選択・文体変換。整形は「変換」であり「応答」ではない（出力検証つき）。

カスタム語彙 + 自動提案

固有名詞・技術用語の誤認識を辞書で矯正。さらに履歴をローカル LLM が分析し、頻出語や矯正パターンを根拠付きで提案 →人間が承認して登録。

履歴 = 監査記録

生テキスト・整形結果・適用プロンプトのスナップショット・モデル名・段階別レイテンシを永続保存。全文検索・再コピー。語彙学習と性能観測の基盤を兼ねる。

ゼロセットアップで開始

SpeechAnalyzer + Apple Foundation Models の組なら追加ダウンロード不要で即使える。品質を上げたければ WhisperKit / MLX モデルを後から導入。

プライバシー = 構造で保証

ネットワークに触れるのはモデルダウンロード用の 1 モジュールのみ。音声・テキスト・語彙・履歴は送信しない。クラウド接続は BYOK 含め非搭載。

非目標: 音声コマンド（アプリ操作）、iPhone 連携・他 OS。v2 候補: 会議録音・ファイル文字起こし。

アーキテクチャ

UIメニューバー / HUD (NSPanel) / 設定 / 履歴 — SwiftUI + AppKit
DomainDictationSession 状態機械・ModeResolver・Vocabulary・FormattingPolicy（AppKit 非依存）
EnginesSttEngine: SpeechAnalyzer / WhisperKit ・ LlmEngine: MLX / Foundation Models（protocol で差し替え）
SystemHotkeyMonitor (CGEventTap)・AudioCapture・TextInserter (ペースト+復元)・ModelStore (唯一のネットワーク境界)
Persistence / AnalysisSQLite (GRDB) + FTS5 ・ 語彙提案バックグラウンドジョブ

状態機械: idle → recording → finalizingStt →（★永続化）→ formatting → inserting → completed。キャンセル・整形フォールバック・クリップボード退避も正規の遷移として扱う。

主要な設計判断

判断理由
完全ローカル・BYOK も無しプライバシーが価値の核。クラウド分岐はネットワーク境界の検証可能性を壊す
macOS 26+ 専用SpeechAnalyzer + Foundation Models で「追加 DL なし」の初期体験。自分専用なので互換負債を負わない
整形完了後に一括挿入即挿入→置換は挿入先との相性問題が既知。レイテンシはストリーミング STT + 小型 LLM で吸収
STT / LLM とも 2 エンジン「ゼロセットアップ」と「品質の天井」の両立。protocol 境界で追加コストは低い
語彙矯正は LLM 整形段が主STT レベルのバイアスはエンジン依存で不安定。LLM 段なら全エンジンに効く
ペースト方式で挿入キーストローク合成は日本語 IME と衝突。クリップボードは退避→復元
語彙の自動「登録」はしない提案 + 人間承認のみ。LLM の確率的抽出を無審査で辞書に入れると劣化がサイレント混入

ロードマップ

  1. M0 スパイク: SpeechAnalyzer 日本語品質 / Foundation Models 整形品質 / MLX 4B 級実測 / ⌘V 挿入互換性 / 言語自動判定
  2. M1 歩くスケルトン: PTT → SpeechAnalyzer → 固定プロンプト整形 → ペースト挿入 + 履歴記録。ここから毎日ドッグフーディング
  3. M2 状態機械完成: ハイブリッド起動・HUD・全フォールバック経路
  4. M3 モード: アプリ別自動切替・ビルトインモード・編集 UI
  5. M4 語彙(手動) + 履歴 UI（検索・再コピー）
  6. M5 エンジン拡充: WhisperKit / MLX・モデル管理 UI
  7. M6 語彙自動提案
